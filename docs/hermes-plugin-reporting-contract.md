# Hermes public-plugin reporting: telemetry, not settlement

Source/document assessment for [issue 87](https://github.com/markdlabrecque/convoke/issues/87), under [epic 61](https://github.com/markdlabrecque/convoke/issues/61). **No plugin/receiver implementation, installation or runtime acceptance.** Bounded 6h human-equivalent scope: reuse/source mapping 2h, reporting/recovery contract 2h, recommendation/review 2h.

## Decision for review

**GO for the usefulness of best-effort diagnostic observations; NO-GO for using those observations as recoverable admission, all-work settlement, lease release or H0 acceptance.** This is a feasibility judgment, not authorization to build or enable telemetry. On the inspected official public surface, a plugin can observe selected tool/turn/subagent boundaries and export bounded facts. It cannot attest complete ownership before effects, fence every producer, or join all caused resources. A trace with matching starts/ends is not a closure certificate; an empty trace is not proof of no work.

No supported public-plugin-only solution to **both B2a and B2b** was established. Consequently unrestricted main-agent Hermes integration remains blocked under the current contract. This finding does not select weaker safety semantics, different tools, a narrower capability set or another architecture. Natural completion has the same missing proof as cancellation; successful ordinary tool turns cannot be assumed to free the lease.

[The API contract](hermes-api-contract.md) remains authoritative: unmodified official Hermes only; no maintained fork, private monkeypatch, overlay, custom build or plugin-delivered core replacement. Shared built-in memory with the configured main agent is intended; no isolated profile/provider. Unknown ownership stays quarantined, uncertain action POSTs are never automatically replayed, and no unrelated main-agent work may be stopped.

### Resource coverage, equally on natural completion and stop

Reuse the accepted resource counterexamples; do not recreate them. O4–O12 confirm the public boundary at B:

- **Handler versus worker:** even actual downstream return covers only that synchronous frame. Timeout/interrupt can emit a terminal tool observation while the worker remains pending. A hook itself can be abandoned on a daemon worker. No public producer seal or exact-resource acknowledgement accompanies the callback.
- **Processes, I/O and finalizers:** direct child exit is distinct from drain/stdin completion, descendant lifetime and cleanup. A deadline wrapper can abandon another thread. Post hooks/result transforms/finalizers may still run after a tool observation. No public observer fact proves those joins.
- **Inline and background delegation:** inline interruption can signal active children, not join them; ordinary authority turn interruption deliberately leaves background delegates. Returned child result, registry terminality and public lifecycle completion do not encompass all child tools, callbacks or transferred processes. No session-wide stop/reset substitute is authorized.
- **Remote accepted work:** local SDK return, cancellation notification, transport EOF or host process exit cannot prove remote job cessation. There is no generic public authoritative remote-join contract. Already committed network/file/memory effects are not rolled back by any stop.
- **Continuations/transfers:** absence of new telemetry cannot fence a future callback or prove a closed resource graph. Parent completion, an empty known-resource set or balanced span counts cannot discharge missing obligations. Intentional background work needs a separately reviewed product contract, not relabelling active work as stopped.
- **Unrelated shared memory:** the main agent can write shared built-in files outside Convoke's ownership. A Convoke lease does not lock those writers. No isolation, reset or memory-integrity claim follows from reporting.

## Identity and lost admission: independent blocker B2a

The actual tool helper returns `task_id`, `session_id`, `tool_call_id`, `turn_id`, `api_request_id`, `conversation_id`. **It does not return authenticated owner scope, durable admission ID, runtime epoch, HTTP public run ID or execution generation.** A provider tool-call ID can be absent, repeated or scoped to another turn. Treat strings as opaque; never parse a provider attempt into a run ID. Do not import private agent/authority state to fill missing fields. [O2,O4]

Convoke may privately pre-journal its local action and the fresh transcript/session identity **before submitting**. This can help route later telemetry from that transcript to a *candidate* action. It is not an atomic server-side admission binding, does not fence arbitrary effects, and does not prove the callback belongs to an exact generation. Scope candidate associations to configured upstream instance/profile + exclusive fresh transcript + active local action; reject ambiguity, shared/foreign sessions and stale generations. Multiple turns on the same socket need separate turn correlation; session match alone must not authorize attachment to the current turn. Never use guessed time windows, tool names or “only one active turn” as authority. A report can remain unbound.

Lost-response trace:

1. Convoke reserves the owner lease and journals a caller-known local action. Native HTTP still creates a public run alias server-side; Runs creates its own UUID. No supported plugin callback atomically binds that local action to a durable owned admission **before execution**. [O10,O11; API contract's accepted recovery trace]
2. Admission/effects may occur before the first response or callback arrives. Observer cancellation shields canonical work; the native alias can disappear. The first report can arrive after effects, or never.
3. A received report supplies observational correlation only. It cannot prove accepted/not-admitted, recover missing owner/generation authority, or safely select a stop target. A tool-free run can have no tool reports at all; a queued run has not reached these hooks.
4. On lost acceptance before run ID, keep admission/lifetime **unknown** and the lease quarantined. No fresh POST, same-key uncertain POST replay, guessed-ID stop, database scraping or broad session stop. A 404, empty report store or expired telemetry proves neither rejection nor cessation.

An authenticated telemetry endpoint cannot manufacture a transactional admission API. `pre_tool_call` policy blocking is too late to be the outer pre-effects fence and is not a durable caller-key reserve/lookup protocol. Local journalling alone and switching to Runs do not close the gap. Existing Runs deduplication's documented **POST replay** is not an allowed read-only lookup under this product policy. Credential rotation, key retention and queued→started races therefore remain B2a requirements, not solved by a reporter credential. [O5–O7,O10,O11]

## Proposed reporting contract V1 — diagnostic only, not implemented

This defines a bounded consumer contract for review, **not new Hermes APIs or an approved phone wire schema**. It deliberately has no `settled`, `resources_empty`, `not_admitted`, `safe_to_retry` or lease-release assertion. Receiver acceptance means only that a sanitized observation was stored. The reporter is trusted code in a powerful Hermes process, not independent attestation or a sandbox.

### Ownership, endpoint and authentication

- A future **Convoke-owned private receiver** could expose only `POST /internal/hermes-observations/v1`, loopback-bound when co-located. Remote use requires separately reviewed private TLS transport/origin; no public bind, redirect, cookies or browser access. No server is created here.
- A separate, narrowly scoped reporter credential authenticates **one configured Hermes source instance/profile**, never a phone, arbitrary owner or run. Distinct from Hermes API and phone credentials. Provisioning/storage/rotation are future owner-authorized work; no secrets are accessed or created now. Never credentials in URL, argv, payload, exception text or logs.
- Receiver resolves source identity from the credential; the body cannot select another source/profile/owner. Only Convoke's server-held action map can attach diagnostic evidence. A valid credential plus matching session **does not confer stop/approval/lease authority**. Do not forward raw IDs or credentials to the phone.
- Rotate the reporter credential without remapping it to a different source/owner. Revoke old credentials explicitly; reject old unauthorized reports, retain any existing uncertainty. Reporter-load IDs scope deduplication, not authority epochs. Unsupported Hermes revision/schema or unknown load is untrusted/unbound, never “safe”. No live version negotiation is asserted here.

### Exact finite envelope and safe statuses

Candidate JSON field set (all identifiers are private opaque values; these are type constraints, not captured IDs):

| Field | Constraint / meaning |
| --- | --- |
| `version` | Integer exactly `1`; receiver additionally pins expected source B and `hermes.observer.v1` in its reviewed compatibility configuration. |
| `load_id` | 32 lowercase hex characters, fresh per reporter load/process; not a Hermes runtime epoch. Credential-bound source must approve a new load out of band; do not auto-promote restarted loads to authoritative. |
| `seq` | Integer 1–9007199254740991, increment for **every attempted local observation before enqueue**; rotate load before exhaustion. Receipt order is not execution order. |
| `kind` | Exactly `tool_pre_observed | tool_terminal_observed | turn_end_observed | subagent_start_observed | subagent_end_observed | reporter_gap`. |
| `outcome` | Exactly `unspecified | ok | error | blocked | cancelled | timeout | incomplete | unknown`; map known callback status/flags without copying diagnostics; unknown upstream value maps to `unknown`. `ok` means observer outcome only. |
| `ids` | Exact keys `session`, `task`, `turn`, `provider_attempt`, `tool_call`, `parent_session`, `child_session`, `child_subagent`; each `null` or 1–256 UTF-8 bytes of bounded control-free opaque text. Missing/oversized/invalid IDs are not truncated into collisions: omit observation and record a gap. No admission/generation is invented. |
| `lost_count` | Integer 0–9007199254740991; zero except `reporter_gap`, where positive means locally known discarded observations. It is not a count of all lost Hermes callbacks. |

All fields required; reject extras, booleans-as-integers, malformed UTF-8/JSON and unsupported enum/version. No unbounded nested values, compression or batches. Maximum request **4096 UTF-8 bytes**; `ids` values collectively at most **2048 bytes**. No prompt, tool name/arguments/results, transcript, reasoning, URL/path, provider request, model output, raw timestamp/diagnostic, exception text, capability handle, memory or approval text. Treat even “sanitized” upstream payloads as too broad; extract only these allowlisted fields. On `reporter_gap`, IDs are all null and outcome is `unknown`. No arbitrary error strings in ACKs/logs.

The receiver records its own bounded receipt metadata and returns only fixed JSON `{"code":"accepted"}` (202) or `{"code":"duplicate"}` (200). Fixed failures: `unauthorized` (401), `invalid` (400), `conflict` (409), `too_large` (413), `overloaded` (429), `unavailable` (503). No reflected IDs/payloads. Unknown outcomes or unbound events cannot drive the phone state machine; existing fixed wire/error semantics remain unchanged. Log at most bounded aggregate counters/fixed codes, not request bodies, identifiers or auth headers. Apply the same rule to framework/access/error logging.

### Bounded delivery and receiver handling

These are proposed engineering limits, not measured Hermes behavior:

1. Hook callback only validates/extracts/enqueues, returning **no behavior-changing directive**; no synchronous HTTP, disk flush, inference or action replay. One exporter with a nonblocking queue of at most **256 envelopes / 1 MiB**, plus one reserved/coalesced gap slot. Never retain raw kwargs. Full queue drops new observations, increments the bounded/saturating gap counter; exporter failure must not propagate raw exceptions into Hermes hook logging. Overflow/serialization failure cannot block a tool or mark it settled.
2. Exporter sends serially, at most **3 attempts per immutable envelope**, each with an absolute **2s** connect/write/read budget and a total **30s** retry budget; maximum queue age **60s**. Retries only for bounded transport/429/503 failures, with finite backoff inside that budget. Authentication/schema/conflict errors stop that load's export and mark reporting unavailable. No redirect following. Exhaustion/age limit discards and schedules `reporter_gap`; inability to deliver even the gap stays unknown. These limits bound exporter work, not remote action lifetime.
3. Re-delivery of the **same observation** is permitted; it never calls Hermes, `next_call`, a tool, approval or stop. Distinguish it categorically from forbidden retry of an uncertain **action**. Lost ACK may mean the receiver already stored the event; duplicate detection prevents new semantics.
4. Receiver key is `(credential-resolved source, approved load_id, seq)`. Identical normalized duplicate is harmless; different content at the same key is conflict, degrades that reporting load and never overwrites evidence. Bound receipt/dedup metadata to **10 minutes**, **4096 entries per source**, rejecting overload rather than evicting silently within that window. It exceeds the sender's maximum delivery age/budget. After retention expiry a late unknown sequence is rejected, not applied anew; if high-water/window state is lost on restart, require load reapproval and mark a discontinuity. No durable-delivery claim.
5. Reordering is retained as observations, not repaired into execution facts. Any missing sequence, terminal without start, repeated tool ID, absent identity, conflicting outcome or callback gap marks the affected diagnostic trace incomplete/unbound. A sequence gap can close if that exact late event arrives, but callback completeness and settlement remain unproven even for contiguous sequences. Do not synthesize starts, stops or canonical results.
6. Reports after local cancellation/terminal/next turn stay historical for their exact private candidate binding, never update a successor or trigger speech/control. Reject foreign/stale identity bindings; unbound reports cannot change owner state. Dedup expiry or deletion of diagnostic payloads never expires an unknown-action identity or releases its lease. Identity-only indefinite-unknown policy remains unchanged.
7. Plugin disabled/unloaded/crashed, hook suppressed/abandoned, exporter disconnected, host timeout/EOF and receiver shutdown/restart all imply **reporting unavailable/incomplete**, not stopped work. Attempt bounded exporter cleanup only; do not drain forever, replay actions or manufacture a final end event. Reload starts a different load ID; it cannot attest a predecessor's missing facts. Missing callbacks before the plugin was loaded cannot be recovered by a later heartbeat. Host generation is not execution generation. [O3,O7,O9]

**Proof gap retained:** finite best-effort queues deliberately lose evidence; adding an outbox could improve delivery but cannot recover a callback never emitted or turn observations into physical joins. Mandatory enforcement would require a supported pre-effects authoritative boundary with no bypass and real source-owned completion obligations. No such generic public plugin contract was found at B. Do not quietly change Hermes's fail-open telemetry policy to obtain one.
